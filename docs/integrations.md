# Live integration setup

## Instagram Login

Configure a Meta app for an authorized Instagram professional account using Instagram Login. Obtain the account ID, user access token and content-publishing permission through the documented Meta consent flow, and set a supported `INSTAGRAM_API_VERSION`. No credentials belong in Git. The application does not implement an OAuth callback/token refresh UI; manage this through your app/account administration or a secure identity service. Verify the required scopes for your selected API version in [Meta's official content publishing guide](https://developers.facebook.com/docs/instagram-platform/instagram-api-with-instagram-login/content-publishing).

Supply immutable video URLs accessible to Meta for the duration of processing; verify encoding, dimensions, duration, music/rights and all frames during content review. The adapter sends `POST /{account_id}/media` with `media_type=REELS`, `video_url`, reviewed `caption` and `share_to_feed`; it persists the container ID, polls `GET /{container_id}?fields=status_code`, and sends `POST /{account_id}/media_publish` only when status is `FINISHED`. Tokens are sent in Authorization headers, never URLs/logs. Other status/error responses stop the job; no success metrics are invented.

Enable `INSTAGRAM_AUTO_PUBLISH=true`, deploy the scheduler, and review a test video. The scheduler will enqueue it automatically within approximately a minute. Disable that flag to require manual `POST /content/{id}/instagram`; disabling daily generation alone does not stop uploads of previously approved videos. Per-account/content/digest job keys deduplicate dispatch. Meta quotas still apply; monitor failures/uncertain states and manage upload pacing before enabling large backlogs.

Reconciliation: publications in `creating` or `publishing` after a crash have an unknown external result. Verify account media/container state before any new request. `processing` with a stored container ID may be polled safely after confirming there was no final publish call, through a controlled audited admin recovery; the app does not blindly requeue expired external jobs. Check the exact review digest again. A result verified as published should receive the correct media ID and job state through your audited admin runbook. Never reset every publication to queued.

## Telegram Stars

Set the merchant support contact and real terms URL before enabling purchases. Set the bot token/webhook secret through deployment secrets. Register HTTPS `/telegram/webhook` with `allowed_updates=["message","pre_checkout_query"]` and the configured `secret_token`. Verify sender/private chat/order/amount/currency checks and pre-checkout latency using Telegram's test environment before live sales. [Telegram's digital payments guide](https://core.telegram.org/bots/payments-stars) describes test setup, Stars checkout, fulfilment and refunds.

The starting price is 250 Stars, with an internal US$5 reference only. This is a configurable business price, not a measured conversion rate. Stars acquisition costs and net proceeds can differ; the bot quotes XTR. Orders freeze price, description, review digest, adult terms self-attestation and terms URL at invoice creation; keep your terms URL versioned/immutable to preserve the accepted text. Do not use ordinary currency/provider-token payments for these digital products.

Create and review a content item, create its product listing, then review title/description/price using reviewer credentials. Listings become active only after approval. The bot invoice uses one XTR price item and a per-order payload. `/buy <product-id> agree` records adult/terms self-attestation without collecting names, addresses, birth dates or child data. No real age/identity verification is claimed. Pre-checkout validates order and current approvals. Only confirmed `successful_payment` transitions to paid and schedules delivery. Receipt writes and job enqueue are convergent on webhook retry, including failure between those steps.

Delivery is protected Telegram video or a `.txt` storybook document, with no public raw asset URL sent in a customer text message. Telegram/Meta must nevertheless access remote asset URLs; use appropriate restricted storage/expiring access compatible with immutable review and processing. This implementation does not provide paid-content access control at your storage gateway, PDF/EPUB packaging, subscriptions, card billing, taxes, or automatic country eligibility checks.

Full refunds use `refundStarPayment`; the charge is bound to the original buyer/order. A refunded event can resolve an uncertain refund and blocks pending fulfilment. A refund cannot retract a copy already delivered/downloaded, and distributed delivery/refund races still require support. The app exposes `/paysupport` and configured merchant contact but does not send unsolicited messages to support staff or implement a ticket system.

When `deliver_order` is uncertain, inspect the private delivery history before changing the order from `fulfilling`; if it was delivered, record the message ID and fulfilled state. If definitely undelivered, revalidate the exact content/listing reviews before a controlled retry. If content is no longer approved, refund. When a refund is uncertain, check Telegram's transaction history and refunded service events before resending. Reconcile any unexpected/multiple charge receipt through merchant support; never treat an arbitrary payment message as permission to deliver.

## Market configuration

Defaults: US primary, English `en-US`, Europe secondary, Asia lower priority. Daily batch starts at 09:00 `America/New_York`, with IANA daylight-saving rules. Existing manifests keep their original timezone/briefs. For a European-first deployment, set `PRIMARY_MARKET`, `CONTENT_LANGUAGE` and `DAILY_VIDEO_TIMEZONE` (for example an appropriate IANA European timezone). These settings guide generation/scheduling; they do not infer customer location, enforce sanctions/tax/consumer requirements, or implement country-specific payment eligibility. Configure those business requirements with your merchant policies and service providers.
